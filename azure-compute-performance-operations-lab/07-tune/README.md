# 07. 튜닝하기

## 목표

VM SKU 또는 Managed Disk 변경을 데이터와 롤백 조건에 근거해 결정합니다.

## 이 단계에서 배우는 것

- D/F/E 계열을 이름이 아니라 workload 특성으로 비교하는 방법
- 성능 개선과 비용 절감을 함께 계산하는 방법
- 변경 전 가설과 변경 후 검증을 분리하는 Change Engineering
- 효과가 없거나 위험할 때 되돌릴 수 있는 롤백 조건 작성

## 의사결정 흐름

```text
병목 증거 → 변경 후보 2개 이상 → 기대 효과·비용·위험 기록
         → 한 가지 변경 → 동일 부하 재실행 → 채택/보류/롤백
```

## 스스로 답할 질문

- CPU 병목이 아닌데 VM SKU를 키우면 어떤 낭비가 생기는가?
- 디스크 tier 변경이 애플리케이션 latency를 항상 개선하는가?
- 같은 p95를 더 낮은 비용으로 달성하는 방법은 무엇인가?

## 실행 순서

1. 기준선 CSV를 보존합니다.
2. 변경 가설을 한 문장으로 작성합니다.
3. 변경 전 SKU·디스크·인스턴스 수를 기록합니다.
4. 한 가지 변경만 적용합니다.
5. `04-baseline`과 동일한 부하를 실행합니다.
6. Before/After 표를 채웁니다.

## 통과 기준

- p95 20% 개선, 또는 동일 성능에서 비용 15% 절감
- 오류율·가용성 악화 없음
- 롤백 방법 기록
